# 1.1.1：QQ 视频附件与大小控制

普通 QQ 视频、作为文件发送的 MP4/MOV/MKV/WebM 等视频，以及会话中的群视频上传，统一进入已有的本机抽帧、音轨转写和分段分析流程。缺少文件链接时，使用 SnowLuma 的私聊或群文件接口获取，保留原有好友、拉黑、群聊参与和视频开关规则。

能力 → 图片与视频新增两个独立大小设置：

- 原视频默认 256MB，可选 32、64、128、256、512MB；在本机流式下载和解码，原视频不上传给模型。
- 每次截图请求默认 4MB，可选 1、2、4、8MB；按 Base64、文字和 JSON 实际大小检查，额外预留封装空间。画面先缩小压缩，超出请求预算时自动分批。

保留 10 分钟时长上限和每秒 1/2/4 帧选项，每次最多 15 张拼图、以 10 万 Token 为规划估算上限。MB 与 Token 分别检查；估算不能替代服务商账单。高帧率和长视频会产生更多请求，不保证整条视频总计少于 10 万 Token。

修复 QQ 附件分析成功却在历史中记为失败的问题；追问使用实际分析记录。收到新视频附件时跳过旧视频搜索。解码失败、超时和超限不会再次下载同一文件。音轨读取同步适配大视频容器，转写音频仍保留原有时长、片段和解码大小约束。

使用同签名 1.1.0 底包的增量补丁；保留账号、API、主动聊天设置、声音和记忆。更新后需支持图片的聊天模型或单独视觉服务。没有取得画面或对白时明确报告失败，不生成虚构分析。
