# 0.1.44：加密配置失效不再阻断 QQ 初始化

针对登录页的 `AEADBadTagException` 修复：旧的加密凭据与 Android Keystore 不匹配时，原先会在创建本机接口凭据阶段直接退出，环境补齐还没有机会运行。这与 Python 缺失是两类问题。重装、恢复数据或系统密钥丢失均可能造成密文不可读；截图本身不足以确定是哪一种。

加密仓库的操作改用进程内共享锁，避免多个 Secrets 实例在界面、服务和健康检查同时创建同一 Keystore 别名、生成相同用途的凭据。读取旧密文时不再悄悄新建密钥；验证失败只将对应项标为不可用，保留原记录，不让可识别的校验异常中断整个服务。

本机接口、QQ 窗口、记忆加密密钥可重新生成；替换前将原失效密文隔离到应用私有加密恢复记录。模型 Key、模型卡片、网站登录和多账号配置不自动编造或恢复：需要在界面重新填写或登录。当前模型卡片不可读时不静默退回旧模型密钥。首次配置界面的新输入明确保存并启用新卡片，避免继续使用失效的旧活动配置。

开始使用、模型及诊断页面提供加密配置恢复提示，不展示密钥或密文。环境诊断明确区分“上次检查缺组件”与当前加密配置错误。保留已有 QQ 容器、账号、聊天和设置，不清空数据、不绕过 QQ 官方身份验证。

旧记忆密钥如果确实丢失，无法凭空解密：沿用现有记忆模块的只保留原文件、暂停持久化保护，不用新密钥覆盖不可读记忆。内置恢复记录也是密文备份，不代表旧数据已恢复或可跨设备解密。

沿用 0.1.43 的 QQ 窗口就绪检测及 Python、图形组件的实际检查和补齐。APK 同包名同签名，内部版本号45，可覆盖0.1.43或更早版本，无需先卸载。

电脑维护工具新增安装记录检查及保留数据回退，见 [ANDROID-REINSTALL.md](ANDROID-REINSTALL.md)。它不是应用中绕过安卓降级限制的功能；ADB 未连接时无法确认手机残留。发布工具支持中断后按文件补传、远端大小和哈希核验，成功后才公开；可用 `--direct-upload` 仅对GitHub上传直连，不改变系统代理。

本版完成 Android 编译、签名、对齐和逐项 APK 资产哈希检查。用户要求停止额外测试，未进行新的 QQ 收发或付费模型调用；手机安装与真实启动情况以本次交付记录为准，不把构建通过当成实机修复通过。
