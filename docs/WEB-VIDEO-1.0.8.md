# 网页视频（本地 1.0.8 / 10014）

## 用法

- QQ 直接发公开视频直链，或发“看看 https://example.com/article 的视频”。
- 普通网页中的 `<video>` / `<source>`、Open Graph 视频、JSON-LD `VideoObject.contentUrl` 可发现视频地址；内嵌 B站播放器转交已有 B站画面读取流程。
- 可以继续问“这个视频说了什么”“看完视频”。从当前会话最近用户链接确定目标，不跳回更早的其他 B站视频。
- 自动联网关闭时需要明确说看视频；“只看正文”“不要看视频”等要求不会触发下载。
- 能力 → 图片与视频中的链接输入也支持网页和视频直链，原有 BV 号仍可用。
- 主人可发 `#来源` 查看实际视频来源和读取范围；普通回答不附技术来源。

## 处理范围与成本

每条消息最多分析一个视频。文件上限 32 MiB、时长上限十分钟，沿用 1/2/4 fps 选择、低清画面和分段预算；画面与本机识别出的对白一起交给视觉模型。音轨识别本身不调用模型，画面与转写文字按模型服务正常计费，不能承诺所有提供商都低于固定 Token 数。

需要支持看图的模型或独立视觉服务；DeepSeek 文字模型不会因此获得视觉能力。
本机通过真实下载的文件提取画面、解码音轨、自动转写，不把网页标题、封面当作完整视频。

只读取公开 HTTPS 的独立视频文件；不执行播放器脚本、不绕过登录/验证码/付费限制。HLS/DASH 分段流、直播及多数需要脚本或登录的其他平台暂不支持。非 B站 iframe 不自动加载播放器。已存在的其他平台分享解析仍以其公开文字/配图为主。

Android 网页探测遇到媒体响应只读取响应头，不将大视频复制进网页正文。原生视频下载逐跳检查 HTTPS 和公开地址，最多三次跳转；不携带模型 Key、其他站点 Cookie 或网页自带的请求头。文件大小、下载时间、解码时长均有上限，失败清理暂存。QQ/B站专用入口仍保持原域名限制。

页面含多个声明的视频时只尝试首个受支持格式；失败明确报告，不以旧画面冒充当前结果。网页、画面和音轨都是低可信资料，不能覆盖系统规则或账号权限。
