# 用户指定网页浏览（本地 1.0.8 / 10013）

## 用法

在 QQ 中直接发送 `https://example.com/article`，也可以把问题放在后面。
大号可使用 `#浏览 https://example.com/article 安装步骤是什么`；普通链接仍按原有群聊和私聊回复权限判断。

- 链接后紧接中文逗号、句号或问题时，分开识别网址和提问；支持 `www.` 自动补全 HTTPS。
- 一次最多读取两个链接，可比较两篇网页；某一篇失败时单独标明，成功页继续提供正文。
- 同一会话可追问“这篇文章的部署步骤呢”“这个网页结尾说了什么”。只从该会话最近八条用户消息确定链接，不借用其他聊天或助手虚构的网址。
- “重新读取这个网页”绕过旧缓存。没有可确定的网址时请用户补发，不凭空搜索或声称打开过网页。
- 大号发送 `#来源` 查看本次真正读取的来源，平时仍不附引用编号和链接。
- 能力 → 联网与网页浏览中的输入框也支持“网址 + 问题”。

## 正文和用量

读取公开 HTTPS HTML/纯文本，支持响应头或 HTML 声明的字符编码（含 GBK）。
下载上限仍为每页 1 MiB；剥离脚本与导航后，最多检查 60,000 字符，
按问题在本机选择正文片段，不额外调用模型做搜索规划或全文摘要。
单页通常不超过 3,200 字符；两页总的网页证据约束在 6,500 字符内。
发给聊天模型的正文会按模型服务正常计算输入 Token，网页读取和本机选段本身不消耗模型 Token。
正文片段不会作为完整网页反复写回聊天历史；持久笔记仍按原有开关和 1,400 字符上限保存。

“结尾/后半部分”选取尾段，其他问题按关键词选择相关片段；这不是完整浏览器、
也不是模型理解全文。长文会明确标记为部分正文；没有声称读取全部内容。
需要登录、访问验证或 JavaScript 才能显示正文的网页可能无法读取。
保留 HTTPS、公开地址、跳转与 DNS 检查；网页请求不携带模型 API Key，
通用网页不复用其他站点 Cookie。网站正文不能成为系统或管理指令。
