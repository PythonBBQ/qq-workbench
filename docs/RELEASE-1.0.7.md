# 七丘 QQ 工作台 1.0.7

设置新增“备份与迁移”和“存储清理”。换设备时先导出一个加密文件，在目标工作台输入备份密码导入。保留 1.0.6 的完整本机语音模型与已选参考。

## 记忆迁移

- 迁移所有账号已保存的对话、摘要、话题权重、事件、养成与长期记忆、语音偏好、学习笔记、人设及上下文设置、API 卡片及密钥、多账号配置、拉黑、表情备注、收藏的自定义音色与背景。
- 文件使用 PBKDF2-HMAC-SHA256 与 AES-GCM 密码加密，不上传云端；导出期间短暂停止本机服务，结束后恢复原运行状态。
- 导入先解密并完整校验，再替换目标数据。导入前另存目标原数据的加密备份；事务中断会回滚，重启时继续恢复。密码无法代为找回。
- 目标保留自己的本机接口凭据；多账号对话和语音记忆重新加密，避免换设备后不可读。API 密钥重新存入目标 Android Keystore，不复制系统密钥密文。
- 不迁移正在执行的 Codex 任务、发送队列、QQ 设备登录凭据和系统授权。新设备可能需要重新登录 QQ，切换前停止旧设备；这不是双设备实时同步。

## 更新源 403

原更新器检查版本只请求 GitHub API，收到 403 就结束。现在依次尝试 API、发行版中的 `update.json`、仓库的 `updates/latest.json`。后两条公开路径不使用 API 配额，不要求填写 GitHub Token。

清单资源必须属于同一仓库、同一版本，保留文件大小、SHA256、包名、版本号与签名检查；下载继续支持进度、断点续传、校验和差分重建。所有通道失败时显示真实失败，不冒充“已是最新”。旧更新器需先安装本次修复才能使用备用路径。

## 存储

清理入口只处理历次试听、探测输出、已替换音色旧副本，保留活动模型、QQ 登录、聊天记忆及用户收藏音色。维护时已将测试文件、旧 NapCat 组件及旧安装包归档到电脑，再从测试平板删除。离线 Ubuntu、官方 QQ、视频转写与语音模型属于正常运行所需文件。

## 验证

真实平板的 54 个持久文件导出加密后约 10 MB，导入隔离目标后记忆可解密，源数据哈希未变。另以合成资料验证四个账号、八份记忆、不同设备凭据、错密码、损坏文件、路径及符号链接拒绝、保存失败回滚和导入前备份。没有覆盖用户真实配置做破坏性导入，也未宣称已在第二台实体设备完成 QQ 登录。

更新源模拟覆盖 API 403、429、超时、受限跳转及备用清单，验证失败不当作成功。本版平板原配置、密钥与当前音色在覆盖安装时逐字节核对保留。真实网络下载与发布结果另按发行后验证记录报告。

发行后实机核验：OPPO 手机原为1.0.5，真实返回GitHub API 403、剩余配额0，确认为共享出口限流。覆盖安装1.0.7时原vault及两份settings逐字节保留。发行后手机分别在模拟API拒绝及API/发行页同时拒绝的条件下，通过真实发行清单、真实仓库索引读到v1.0.7；1,021,286字节补丁下载并通过SHA256校验，测试未再次安装。平板共归档并移除2,143,196,775字节的测试及旧安装数据。1.0.5/1.0.0升级补丁约443MB，因新增完整语音模型；1.0.6升级约1MB。
