# 0.1.43：QQ 登录窗口就绪检测与环境自动补齐

QQ 登录页不再进入后立刻加载本机网页。先核对对应账号的 noVNC 页面及桌面服务，准备好后才显示窗口并启用识别按钮；未就绪时显示初始化进度、服务状态及诊断入口。主账号和独立账号共用相同逻辑；离开页面或切换账号后旧请求不能打开另一账号的窗口。连接中断时隐藏浏览器错误页并重新检查，不把本机连接凭据暴露在默认网页错误页里。

启动时实际检测 Python 3 标准库、websockify、Xvfb、x11vnc、桌面会话、noVNC 网页、官方 Linux QQ、QQ 动态库和 SnowLuma Node。旧的安装完成标记不再跳过检查。缺失的内置 Python 文件优先从 APK 恢复；保留现有非空文件和账号配置。构建时从固定归档生成623个Python文件清单，包含 mmap 等原生扩展。Node 程序缺失时重新导入内置运行时。

缺少的图形或Python组件通过容器的系统软件源补齐，再复检后启动QQ。安装操作使用固定软件包允许列表和运行锁，避免与其他下载并发；检测器本身无法运行时使用固定基础包列表恢复。下载、DNS、存储和包管理器锁问题显示可重试提示，不清空QQ账号、聊天、模型密钥或人设。环境健康时不重复下载必需组件。可选视频组件仍单独准备。

设置→诊断增加逐项检测结果、“重新检测环境（不下载）”和“自动补齐并重新启动”。重启会先等旧会话退出，避免同时启动两个QQ。启动脚本也等待网页登录组件与桌面组件实际就绪，失败时报告对应组件，不再仅凭后台进程创建成功继续。

实际检查的OPPO PHU110、Android 15：最初连接时本地会话未运行；重新打开旧版后，登录网页返回200并显示QQ扫码窗口，九项环境检测均通过。因此该机当时未发现Python或网页组件缺失；此前会话为何停止，现有日志不足以确定。新版已在该机保留配置覆盖安装，安装包SHA256匹配，启动后基础环境检测通过，登录窗口恢复显示。尚未完成QQ登录，不声称该机聊天收发已验证。

已完成205项Node回归、5项环境检测测试、6项实际安装脚本的隔离故障模拟，以及10项Android框架检查。覆盖健康环境不下载、旧标记下仍检测缺失、网络失败、未知包拒绝、检测器损坏后恢复、HTTP/RFB真实本机套接字和内置文件恢复。Android测试工具对OPPO的上下文初始化及进程退出作适配；不修改真实用户协议确认。安装包签名、对齐、资产内容与新修复类核对通过。

用户要求停止后续测试，未将短时断开ADB观察作为完成的验证，也未验证长期熄屏。无线调试恢复与重新打开应用发生在同一排查过程中，不据此声称ADB是应用运行依赖或认定系统后台回收的具体原因。

覆盖更新即可，无需卸载。首次联网补齐时保持应用打开并留出空间；初始化失败可在诊断查看具体项后重试。第三方组件继续适用其原许可。
