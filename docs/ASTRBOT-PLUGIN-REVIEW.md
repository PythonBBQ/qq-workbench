# 截图中的 AstrBot 插件评估

核对日期：2026-10-30。范围：公开 GitHub 文档、插件元数据、依赖文件和入口源码，对照工作台现有实现。未安装插件、未改应用运行逻辑、未构建 APK，未发送 QQ 消息或发布空间动态。

## 多平台内容解析器 v1.3.0

- 仓库：https://github.com/Qfxaile/astrbot_plugin_multi_parser
- metadata.yaml 版本与截图一致：v1.3.0；MIT 许可，复用代码应保留版权和许可。
- 自动读取链接或分享卡片，覆盖 B站、抖音、小红书、微博、知乎、微信公众号、GitHub 仓库等。不同平台有不同支持范围；部分解析需要用户配置该平台 Cookie。
- 支持将解析文字或图文加入 AstrBot 会话，并可调用模型总结。这些选项不是默认全部开启。
- 解析媒体地址或返回视频不等于模型已观看视频。视频理解仍需视觉模型及帧/音频处理链。
- Python 3.10+，入口继承 AstrBot Star，依赖 AstrBot 事件、消息链、配置和会话服务；不是直接可插入当前 Node/安卓工作台的独立包。
- 建议优先移植独立的平台解析能力，将有来源标识的文字/图片送入工作台已有上下文，不另起一个聊天框架。

## QQ空间 v3.1.3

- AstrBot 插件集合登记的同名项目：https://github.com/Zhalslar/astrbot_plugin_qzone
- 登记描述与截图一致：查看/点赞/评论、自动发说说、AI写说说及表白墙投稿审核。
- 核对时该原仓库 API 和原始文件均返回 HTTP 404，无法确认原版 v3.1.3 的当前代码与许可；不能据截图声称原版仍可安装或已验证。
- 可读取的衍生项目：https://github.com/diaomin66/astrbot_plugin_qzone_ultra 。其 README 描述 OneBot Cookie 自动绑定、空间读写、评论、点赞及独立 daemon；仍依赖 AstrBot 兼容层，尚未在工作台或安卓设备验证。
- 另一个可读取的改版 https://github.com/sujingyi1/astrbot_plugin_qzone 标注 v2.1.0，名称、版本均不同，LICENSE 为 GPLv3。不能把它当作截图原版，也不能按 MIT 许可直接搬运。
- 当前工作台已经有空间文案、草稿、文字发布及 SnowLuma 凭据接入。新增价值主要是动态正文读取、评论/点赞、图文或视频发布；这些都需要独立适配和实测。
- 当前 qzone-client 的只读检查仅验证返回结构，没有向 AI 返回真实动态正文；不能据检查成功宣称 AI 已读过空间动态。

## 表情包管理器 5.2.10

- 仓库：https://github.com/anka-afk/astrbot_plugin_meme_manager
- metadata.yaml 版本与截图一致：5.2.10；MIT 许可。
- 明确要求 AstrBot >=4.17.0；截图底部内置插件的 4.4.0 字样不能单独用来判定实际框架版本。
- 提供资源广场、表情包安装、分类管理、会话/人格选包、自动收集、语义检索和云同步。
- 普通分类方式无需额外选图模型或向量索引；辅助选图、图片描述和向量检索可能增加模型费用。依赖包括 Pillow、faiss-cpu、aiohttp、MinIO 等，安卓移植前需检查本地库兼容性。
- 工作台已有 QQ 收藏读取、真实主人发指令收藏、AI备注及语境选图。适合补充分类预览、资源包导入和按会话选包，避免重复建设收藏链。
- 保持当前权限：收藏和管理仅限配置中的真实主人，不因移植而启用收集所有人的图片。

优先做多平台链接进入聊天上下文，其次补充表情分类/资源包，最后扩展空间互动。三个插件均不能仅复制目录就接入现有工作台；若日后采用 AstrBot 运行时方案，需要另行评估安卓依赖、后台资源和现有账号/权限路由。
