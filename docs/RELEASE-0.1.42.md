# 0.1.42：口语输出、独立语音偏好与提示词精简

语音与文字的形式选择、语气和正文仍由原本同一次聊天请求完成，不增加一次判断或润色请求。明确要求文字、近期不方便听、仅要求时语音等情况，直接使用简短文字规则；不确定时让聊天模型结合上下文选择。说话更侧重先接住话题、一到三句、自然标点，不用动作旁白、固定撒娇或呼吸标签。人设仍由酒馆统一管理，不冒充真实人类或编造现实活动。

新增独立的 `voice-memory.json`，使用本机派生密钥加密。只保存文字/语音倾向、语速、长度、语气和语气词的明确偏好，不复制完整聊天或让助手给自己编造偏好。按机器人、大号设置、联系人和群隔离，独立于酒馆角色；切换大号不会继承原大号的偏好。“以后语音短一点”可以保存；刚收到语音后明确说“慢一点”也可学习，临时“今晚不方便听”不记为长期偏好。可在“能力 → 语音”关闭学习、查看或清除，不影响其他记忆。

语速直接交给本机合成器，不写入模型提示词；只发送影响措辞的几项短偏好。已由独立偏好覆盖的旧普通偏好不重复注入，新的明确语音偏好不再另存为普通偏好。最近对话仍保留以承接上下文；没有声称所有重复语句均已消除。

用户指定的常驻规则从416字符压缩到230字符，减少44.7%；这只是该段文本的字符减少，不能等同于总请求Token或费用降低44.7%。视频对白、画面与来源细则仅在相关话题注入。是否命中缓存及实际Token由模型供应商用量回执为准。

合成前清理控制标记、常见动作旁白、表情和冗余标点，保留有意义的括号、英文、版本号和普通数字；百分数、摄氏度转成可读形式。ZipVoice在推理前就规划短语，目标约18字，优先附近的句号、逗号和语意边界，避免过短的尾句；不硬切单词、版本、小数或括号内容。找不到安全边界时保留较长原句。相同参考音色与语气逐段合成，所有片段完成后才拼成一条语音；逗号停顿短、句号停顿稍长，处理音频边缘与过高峰值。共用一次排队和截止时间，不改变声高、不加假呼吸。Android、Azure、QQ及肥鱼后端使用各自支持的输入形式。

分段依据本次平板校准：肥鱼温柔参考、8步、原语速-30%，7/14/18/31/45字各合成两次，共10次均返回音频。18字两次耗时约13.5/13.8秒，本机ASR均与该样本正文一致；7/14字有错读、多读或识别偏差，因此没有采用机械最短字数。18字是当前设备小样本的保守目标，不是每段必须18字，也不是所有文本准确率承诺；实际分段长度随合成回执记录。本机断句、拼接和测试转写不新增聊天模型调用。

针对语音中途停止，设备旧版的103字测试正文曾触发合成超时。核对上游2.0.1发现中文逐字计入默认5/20词分段，容易产生很多小片段并强制切开长分句；适配明确设置为30/70，外层预先组织短语。合成等待及界面、多号、执行端超时一起扩展至约两分钟。新增中断标记、每段空音频/异常短时长检查，所有外层片段完成才转换发送，状态保留字数、音频时长和完成段数。最终仍失败时，完整正文按标点就近分成两段文字，用一条QQ消息发送，短内容不强拆，不重试、不丢尾句、不额外添加报错段落；没有在失败后才开始规划语音分段。不使用付费转写或再调用模型判断；时长与计数只能检查明显异常，不能保证每字都读对，不能替代听感确认。

新增“本机语音长句自动加速”（默认开启）：超过60字时在提交前选择4步，短句保持用户选择的4/8步，原语速保留；可关闭以固定精度。实际步数随合成回执记录，不在超时后反复重试。测试账号原为8步、语速-30%，103字正文在旧版约65秒超时；中间候选的两大段4步约32秒完成。最终APK实机验证：24字8步约8秒，103字提前规划为18/27/18/20/20字五段，4步约39秒完成、音频约28秒；同样五段固定8步约73秒完成、音频约31秒，超过旧截止时间仍完整返回。短分段也增加了推理开销，没有声称越短越快或4步和8步音质等同。仅本机测试与转写，未新增付费聊天调用、未发送QQ测试消息。

205项完整Node回归、8项Android框架检查通过。程序检查覆盖偏好隔离、加密、更新和清除，当前消息覆盖旧偏好，临时要求不长期保存，输入去重、按需提示词和合成传参；Android检查覆盖提前短语规划、完整内容保留、数字/版本/括号保护、标点停顿、边缘处理、峰值与拼接。最终4/8步103字音频均经本机ASR检出首尾，但中间仍有少量错读、漏读或识别偏差；完成计数只证明各段返回，不证明逐字正确。听感自然度、人物相似度、不同话题的选择效果仍需要实际试听和后续聊天反馈，不能仅凭测试断言真人效果。
