# 1.0.8 本地回复修复（内部版本 10010）

用户报告私聊两句后停止、暂停再开启暂时恢复。本轮没有发布 GitHub。

## 真机现场

连接设备为 PHU110 / Android 15。停住时 Java 主进程、proot 与 Node 等待通道为 `do_freezer_trap`，本机 `/state` 超时，持久化健康检查停止增长，旧记录仍显示 QQ 在线。设备前台为哔哩哔哩。本次现场能确认系统冻结，不能据此断言用户描述的每次前台停答均由同一原因造成。

ColorOS 的「允许应用后台行为」原为关闭、异常耗电为自动优化；本轮在系统界面开启后台行为，回读显示开启、不优化。工作台恢复可达。通知仍未确认开启：ADB 授权命令被系统权限限制拒绝，不能将此项计为成功。

## 源码修复

- 删除发送未知后的按时间静默丢弃新消息机制。未知原消息仍保留账本且不重发，后续新消息等待连接核验。
- 回复任务持有独立取消信号；依赖最多等待 180 秒，单任务总上限 15 分钟，模型原有 90 秒等更短超时继续生效。超时释放队列，迟到结果不能继续发送。
- 暂停/恢复和配置切换取消旧任务。主人在 QQ 发回复开关指令也能中断正在等待的旧任务。
- 主界面显示模型等待、语音合成、QQ 发送、处理秒数与排队数量。本地接口失败时清除缓存在线显示；后台健康检查失败撤回在线标志，90 秒以上的健康记录标为过期。
- `tools/inspect-live-replies.py` 只输出诊断白名单，不输出密钥、消息正文或模型输入。

## 验证与交付

49 项相关单元回归通过，完整助手隔离流程通过；流程包含永不返回且不响应取消的模拟模型、暂停取消后连续 8 轮私聊、未知发送凭据后的新消息恢复。测试使用真实捆绑解析器和隔离网络桩，不发送真实 QQ 消息。

生产 Java 编译、D8、APK 签名、对齐及保留资源逐项哈希验证通过。所有音色、模型与大型资源保持官方 1.0.7 内容。
